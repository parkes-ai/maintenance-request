# 사이트 설계도(PRD) v2 — 유지보수 접수 대장

작성일: 2026-10-10 · **개정: 2026-10-11 (v2)** · 이 문서는 사이트를 고칠 때마다 다시 보는 기준이다.
참고 자료: `유지보수_접수대장_사업개요_검토본2.pdf`, `접수대장_기획서.pdf`(부록 A 참조 명세). v1(첫 설계도)에서 바뀐 이유는 맨 아래 "개정 이력".

## 1. 한 줄 정의
납품한 프로그램(SAP 유지관리·추가 개발 포함)의 유지보수 요청을 **한곳에 빠짐없이 기록**하고, 고객사별 처리 시간과 무상 응대 시간을 숫자로 보여 주어 **유상 전환의 근거**를 만드는 접수 대장.

## 2. 사람과 입구
| 누구 | 들어오는 길 | 하는 일 |
|---|---|---|
| 고객사 담당자 | 고객사 **전용 링크**(`/r/코드`) | 요청 남기기 (로그인 없음). 링크에서 가입·로그인하면 **그 회사 요청 전부**의 상태 보기, 유상 작업 동의 |
| 처음 연락하는 회사 | 사이트 첫 화면 | 회사 이름을 적어 요청 → **"신규 문의"**로 따로 모임 |
| 관리자(나) | `/admin` 비밀번호 | 전부 보기·처리·기록·관리 |
| 처리 인력 | 시스템에 들어오지 않음 | 담당자로 지정됨 (이메일 알림은 메일 설정 뒤) |

## 3. 손님 화면
- **첫 화면**: 큰 문장 + [유지보수 요청하기] + 답변 안내(버튼 옆) + 처리 단계(접수 → 처리 중 → 완료)
- **요청 폼**: 이름(필수) · **이메일(필수)** · 전화(선택) · 프로그램 · 요청 종류 · 급한 정도 · **본문(메일처럼 글 중간에 이미지)** · **첨부파일** · 민감정보 주의 안내 · 동의
  - 회사: 전용 링크면 자동(바꿀 수 없음), 아니면 직접 적기
  - 입력하는 동안 **같은 고객사의 비슷한 요청**을 최대 3건 안내 (접수는 막지 않음)
- **접수 완료**: 접수번호 크게 (`코드-년도-일련번호`)
- **내 요청 내역**(로그인): 그 회사 요청 목록·본문·첨부, 상태는 고객용 4가지(접수됨 · 처리 중 · 확인 필요 · 완료), **유상 작업 동의/거절**
- 고객에게 **보이지 않는 것**: 우선순위, 응답 목표, 담당자, 처리 시간, 작업 기록, 원인, 청구 방식, 메모, 변경 기록

## 4. 관리자 화면
- **요청함**: 지금 기능 유지(상태별·구분·급한 정도·검색·48시간 알림·30일 추이·CSV·선택 삭제·변경 기록) + 아래 처리 항목
- **요청 처리(카드 안 펼침)**: 우선순위(긴급·보통·낮음) · 유형(장애·서비스 요청·변경 요청) · **원인**(우리 결함·사용 문의/교육·추가 요청·고객 환경) · 담당자 · 상태 5가지(새 요청·배정·처리 중·완료·보류 사유) · **청구 예외** · **작업 기록**(날짜·방식·분·내용, 여러 줄) · **응답 목표 시각**(영업시간 기준) · **유상 승인 요청**
  - **완료 조건**: 작업 기록(처리 시간) 1분 이상 + 원인 선택
- **요청 등록**: 전화·이메일로 받은 요청을 직접 입력 (접수 경로 · 고객사 **검색·고르기** · 요청자 · 본문·첨부)
- **고객사**: 추가(이름·청구 방식·월 정액 포함 시간·담당자 연락처·계약 메모) · 링크 복사·새 링크·사용 중지
- **인력**: 이름·연락처·가용 시간·재직/퇴사 (퇴사해도 이력 유지, 배정 목록에서 빠짐)
- **월 요약**: 고객사별 월 건수·완료·처리 시간·무상 응대 시간·무상 비율·원인별·유형별·응답 목표 달성률, 월 정액 사용률 → **월 응대 보고서**(인쇄·PDF 저장, 고객 공유용)
- **회원**: 지금 기능 유지

## 5. 규칙
| 항목 | 규칙 |
|---|---|
| 접수번호 | `고객사코드-년도-일련번호(4자리)`, 고객사 코드는 추가할 때 C001, C002 …로 자동으로 붙고 바꿀 수 없음. 신규 문의는 `NEW-…`. 해마다 0001부터. 한 번 붙으면 바뀌지 않음 |
| 본문 | HTML이 아니라 **글 조각과 이미지 목록**으로 저장 → 넣은 코드가 실행되지 않음. 글 1자 이상 또는 이미지 1장 이상 |
| 본문 이미지 | 요청당 5장, PNG·JPG(자동으로 줄여서 저장) |
| 첨부파일 | 요청당 5개, 파일당 10MB, PDF·엑셀·워드·한글·PPT·ZIP·TXT·로그·이미지 |
| 제출 제한 | 전용 링크: 1분 3건·1시간 20건 / 신규 문의: 같은 접속 위치 10분 3건 / 파일 올리기도 제한 |
| 우선순위 기본값 | 급한 정도에서: 업무 중단 중·급함 → 긴급, 보통 → 보통 (관리자가 확정) |
| 응답 목표 | 평일 09–18시(한국 시간)만 셈. 긴급 2시간 · 보통 9시간(1영업일) · 낮음 27시간(3영업일). 영업시간 밖 접수는 다음 영업일 09시부터. 우선순위가 바뀌면 다시 계산. **관리자만** 봄. 공휴일은 나중에 |
| 첫 응답 | 요청이 '새 요청'에서 처음 다른 상태로 바뀐 시각 (답변 이메일 기능이 생기면 그 시각으로) |
| 무상 응대 시간 | 그 요청의 청구 방식이 무상 또는 계약 범위 안인 처리 시간 합. 청구 방식 = 요청 예외 > (원인이 '우리 결함'이면 무상) > 고객사 청구 방식 |
| 월 기준 | 접수한 달(한국 시간)로 셈. 다음 달에 처리 시간을 넣으면 지난달 숫자가 바뀔 수 있음 |
| 자동 이메일 | **완료되는 순간** 요청자에게 완료 안내 (접수번호·완료 시각). 메일 서비스 설정 전에는 보내지 않고 관리자 화면에 "설정 전" |
| 유상 승인 | 관리자가 예상 시간·설명을 적어 요청 → 고객이 내 요청 내역에서 [진행 동의]/[동의하지 않음] → 누가·언제 기록 |
| 고객 분리 | 다른 고객사의 요청·본문·첨부는 어떤 경우에도 보이지 않음 |
| 보관 | 완료 후 1년 지나면 요청·이미지·첨부·기록 자동 삭제(매일 새벽). 회원은 탈퇴 즉시 삭제 |

## 6. 이번에 넣지 않을 것
결제 · 인력 로그인 · 받은 이메일 자동 접수 · AI 보조(2단계, 복사 방식) · 공휴일 목록 · 답변 이메일·접수 확인 이메일(완료 안내만 먼저) · 공개 도메인 연결(메일을 쓰려면 필요)

## 7. 사용자가 직접 할 일
1. Supabase Site URL 설정 (회원가입용)
2. 메일 발송: 도메인 준비 → 메일 서비스(Resend 등) 가입·도메인 인증 → Vercel 환경변수 `RESEND_API_KEY`, `MAIL_FROM`
3. 고객사 청구 방식 정하기, 실제 전화번호 확인

## 8. 만드는 방법
- HTML + Vercel `/api` 함수 + Supabase(표·파일 저장소·회원), 디자인은 에디토리얼 스타일(`assets/style.css` 하나)
- 비밀값은 환경변수만, 표는 행 보안(RLS) 켜고 정책 없음 → 서버만 접근
- GitHub main에 올리면 자동 배포
