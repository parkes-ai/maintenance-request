# 사이트 설계도(PRD) — 유지보수 요청 접수 (가칭, 이름 미정)

작성일: 2026-10-10 · 이 문서는 사이트를 고칠 때마다 다시 보는 기준이다.

## 1. 한 줄 정의
내가 납품한 프로그램을 쓰는 고객사 담당자가 오류·수정 요청을 글과 화면 캡처로 남기는 접수 사이트.

## 2. 손님
- 누가: 고객사 담당자. 프로그램을 매일 쓰는 현업 실무자(컴퓨터에 익숙하지 않을 수 있음)와 고객사 IT 담당자 둘 다
- 어디서 알고 오나: 내가 카톡·문자로 보낸 링크 → 휴대폰에서 처음 열 가능성이 큼

## 3. 손님이 궁금한 것 (요청을 남기기 전에)
1. 언제 답을 받나
2. 무료인지 유료인지
3. 내 요청이 잘 접수됐나
4. 급할 땐 전화가 되나

## 4. 믿게 할 증거 (실제로 있는 것만)
- (미정) — 접수 사이트라서 홍보용 증거보다 "접수 완료 확인"과 "연락처가 분명함"이 믿음을 준다
- 후기: 이번엔 넣지 않음

## 5. 누르게 할 버튼 하나
- 버튼 이름: 유지보수 요청하기
- 누르면: 요청 폼

## 6. 페이지 구성 (위에서 아래로)
1. 첫 화면 — 한 문장 + [유지보수 요청하기] 버튼
2. 안내 세 줄 — 답변 시점 · 비용(계약에 따름) · 급하면 전화
3. 요청 폼 (글 + 화면 캡처 첨부)
4. 접수 완료 화면 — "접수됐어요" + 접수 번호
5. 아래쪽 — 긴급 전화번호, 개인정보 처리방침 링크
- 별도 페이지: 회원가입·로그인, 내 요청 내역, 개인정보 처리방침, /admin

## 7. 요청 폼에서 받을 것
- 이름, 연락처
- 회사(고객사) 이름
- 어느 프로그램인지 (선택 목록 — 프로그램 이름은 만들 때 입력)
- 요청 종류: 오류 / 수정 요청 / 사용 문의
- 급한 정도: 보통 / 급함 / 업무 중단 중
- 요청 내용 (글)
- 화면 캡처 첨부 (이미지 파일, 여러 장 가능)
- 개인정보 수집·이용 동의 (필수)

## 8. 정확해야 하는 사실 (사용자가 말한 그대로)
- 비용: 계약에 따름 (무상/유상 범위는 확인 후 안내)
- 답변 시간: 아직 정하지 않음 → 사이트에는 "확인 후 연락드립니다"로만 적는다. 숫자를 지어내지 않는다
- 위치: 해당 없음
- 연락 방법: 이 사이트로 접수 + 급할 땐 전화 (전화번호는 만들 때 사용자가 입력, 지금은 빈칸)

## 9. 이번에 넣지 않을 것
- 결제
- 알림 메일·카톡 자동 발송
- 후기·포트폴리오 섹션
- 블로그·공지 게시판

## 10. 첫 화면 한 문장 후보
1. 프로그램에 문제가 생겼나요? 화면을 찍어 남겨 주시면 확인 후 연락드릴게요.
2. 오류·수정 요청, 여기에 남겨 주세요.
3. 캡처 한 장이면 충분해요. 유지보수 요청을 접수해 주세요.

## 11. 다음에 할 것
- 답변 시간 기준 정하기 (정해지면 첫 화면 안내에 숫자로 넣기)
- 새 요청이 오면 나에게 알림(메일·카톡)
- 처리 상태가 바뀌면 고객사에 알림
- 사이트 이름 정하기

## 12. 만드는 방법 (클로드가 끝까지 만들 때 기준)
- 분위기: 깔끔한 (업무용 도구답게 단정하고 읽기 쉬움, 휴대폰 먼저) · 참고 디자인: 없음 — 클로드가 정함
- 문의 저장: 예 → Supabase(leaderpl-admin 스킬) + /admin
  - 화면 캡처는 Supabase Storage(파일 저장소)에 저장, 관리자만 볼 수 있게
  - /admin: 요청 목록 · 캡처 보기 · 상태(새 요청 → 처리 중 → 완료) · 급한 정도로 걸러 보기
- 회원가입: 필요 → Supabase Auth
  - 고객사 담당자가 로그인하면 "내 요청 내역"과 처리 상태를 볼 수 있다
  - 개인정보 처리방침 페이지가 반드시 필요하다 (수집 항목·목적·보관 기간·연락처)
- 배포: GitHub 공개 저장소 + Vercel

## 13. 만드는 순서 (클로드가 처음부터 끝까지 한 번에)
1. 스타일(색·글꼴)을 분위기에 맞게 정하고 첫 화면부터 만든다
2. GitHub 공개 저장소에 올리고 Vercel로 배포해 내 주소를 만든다
3. 요청 폼 → Supabase 저장(글 + 캡처) → /admin 관리자 페이지까지 만든다
4. 회원가입·로그인 → 내 요청 내역 페이지 → 개인정보 처리방침 페이지를 만든다
5. 다 만든 뒤 한 번에 보고: 내 사이트 주소 · 관리자 주소 · 확인 방법 · 사용자가 할 일
- 사용자가 직접 할 일(이때만 멈춤): 로그인, 결제, 관리자 비밀번호(ADMIN_PASSWORD) 입력, 긴급 전화번호·프로그램 이름 입력
